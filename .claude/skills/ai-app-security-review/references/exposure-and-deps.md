# 公開設定と依存パッケージ

この2つは性質が違うが、どちらも「アプリのコードは正しいのに、
周辺の設定で壊れる」タイプなので、まとめて見る。

## 到達範囲（誰がこのアプリに接続できるか）

認証がないアプリでは、**到達範囲がそのままアクセス制御**になる。
つまり待ち受けアドレスが唯一の防御線であり、ここが開くと
「誰でも、その人の鍵で、その人の履歴を読み書きできる」状態になる。
だから設定1行の話でも深刻度が跳ね上がりうる。

### 設定ファイルだけで判断しない

`.streamlit/config.toml` に `address = "localhost"` と書いてあっても、
実行時に上書きされていれば意味がない。上書き経路を全部見る。

1. 設定ファイル（`.streamlit/config.toml`）
2. 起動スクリプト（`run.bat` / `.sh` / `.ps1` の `--server.address`）— `scan.py` が検出
3. 環境変数（`STREAMLIT_SERVER_ADDRESS` など）
4. 実行時のコマンドライン引数
5. コンテナやリバースプロキシ経由の公開

設定ファイルだけ見て「localhost限定なので安全」と書くと、
起動スクリプトが `0.0.0.0` を渡していた場合に致命的な見落としになる。
必ず起動経路まで追う。

### 設定ファイルが無い場合

無ければ既定値が効く。既定で全インターフェースに待ち受ける実装なら、
「設定ファイルが無い」は「LANに公開されている」と同義になる。
既定値を確認せずに「設定なし＝問題なし」としない。

### XSRF / CORS

Streamlit は XSRF 保護が既定で有効。既定のままなら指摘不要。
`enableXsrfProtection = false` と **明示的に切っている場合だけ** 書く。
「設定が明示されていない」ことを欠陥として書かない。既定が安全側なら、それは正常である。

## 依存パッケージ

### バージョンが固定されていない

`streamlit>=1.40.0` のような指定は、次に入れ直したとき何が入るか分からない。
ここでの本当のリスクは2つあり、混ぜないほうがよい。

1. **再現性** — 動いていた環境が再現できない。セキュリティの問題ではない。
2. **供給網** — 依存またはその依存が乗っ取られた版を引き込む。
   引いたコードは **あなたの権限で動く**。`.env` も履歴も読める。
   個人ツールでも影響は大きい。

発生確率は低いが影響は大きい、という書き方が正確。
「今すぐ危険」と煽らず、「固定しておくと、その日が来たときに被害を受けない」と書く。

対処は `pip freeze > requirements.lock`、あるいは `==` での固定。
コード変更を伴わないので、勧めやすい部類の対策である。

### 古いまま放置されたライブラリ

外部データを解析するライブラリ（PDF、画像、圧縮）は、
細工されたファイルで不具合を踏む余地がある。
他人からファイルを受け取る運用なら、これらを最新に保つ意味は大きい。
自分の書いた文章しか入れないなら優先度は下がる。
**脅威モデル次第で優先度が変わる**ことを明記する。

### 実行環境

- 仮想環境（`.venv`）を使っているか。グローバル環境に入れていると、
  他のプロジェクトと依存が混ざる。
- 仮想環境が `.gitignore` に入っているか。

これらは衛生の話であって脆弱性ではない。所見に混ぜるなら低として、
「セキュリティ上の問題ではないが」と断ってから書く。
